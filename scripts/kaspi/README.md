# Подготовка импорта Kaspi

Это первый этап: скачивание карточек и фотографий в локальную папку
`kaspi-staging/` (исключена из git). На сайт ничего не публикуется.
Скрипт не использует ИИ и не расходует токены модели.
Нужен Node.js 22.18+ или 24+ для запуска TypeScript.

```powershell
npm run kaspi:prepare -- --url "https://kaspi.kz/shop/p/altea-22-72-0000-41105-razmer-19-ves-4-01-g-serebro-bez-vstavok-137300269/?c=750000000&m=IPKOJEVYATOVA"
npm run kaspi:prepare -- --links products.txt --limit 5
npm run kaspi:test
```

В `products.txt` — по одной ссылке на карточку в строке. Общее число в
прогрессе — число уникальных ссылок в этом файле, а не размер магазина.
По умолчанию за запуск обрабатываются не более 5 новых карточек.

Прогресс показывается в терминале: готовые товары, фотографии, ошибки,
скорость. `progress.json` обновляется после каждой карточки.
Фотографии сохраняются без расширения; их формат определяется по содержимому.
В `product.json` остаются исходные ссылки, характеристики и список файлов.
Цена карточки — справочная: принадлежность цены конкретному продавцу ещё
не проверена. ID Kaspi не является артикулом продавца из XML.

Ctrl+C останавливает работу после текущей карточки. Повтор той же команды
пропускает готовые товары и повторяет неудачные. После аварийного завершения
может остаться `kaspi-staging/run.lock`: удалять его можно только убедившись,
что предыдущий процесс остановлен. Не редактируйте progress.json вручную.

## Полная замена каталога (добавлено 9 сентября)

`npm run kaspi:collect` собирает страницы магазина IPKOJEVYATOVA через
актуальные публичные адреса из JavaScript Kaspi и проверяет предложения
этого продавца. Затем автоматически скачивает карточки и фотографии.
Цены и артикулы продавца находятся в `merchant.json`; цена самой карточки
в `product.json` по-прежнему только справочная.

Прогресс: откройте `/import` на локальном сайте (`npm run dev`).
Список собирается по конечным категориям, чтобы не упираться в предел общей
пагинации. Полнота подтверждается сравнением числа уникальных ID с итогом
Kaspi и суммой категорий. При несовпадении, ошибке доступа или отсутствии
предложения продавца сбор останавливается, замена запрещена.
`collect.lock` предотвращает два параллельных запуска; после аварии
удаляйте его только после проверки, что процесс действительно остановлен.

После скачивания всех фото войдите в аккаунт владельца каталога и нажмите
«Перенести и заменить старый каталог». До завершения загрузки держите вкладку
открытой. Каждый новый товар сохраняется черновиком, фото — в Supabase Storage.
Повторный запуск продолжает ту же задачу. Старые товары удаляются и новые
публикуются одной транзакцией только при полной загрузке ожидаемых ID.
Если исходные товары изменились, финализация останавливается.

Снимок доступного публичного каталога сохранён в `backups/`. Полный снимок
строк владельца дополнительно сохраняется в `catalog_import_jobs` перед
загрузкой. Это копии записей, а не резервная копия всей базы и Storage.
Сохранённые заказы не удаляются; старые ссылки на карточки перестанут работать,
избранное/история старых карточек удаляются согласно существующим связям БД.

Миграции: `20260909164043_kaspi_catalog_replacement.sql` и
`20260909164737_guard_catalog_import_uploads.sql`. Они уже применены в текущем
проекте. Для другого проекта применяйте через `npm run db:push`.
Запись доступна только через авторизованный аккаунт владельца. Секретные
ключи и пароли сборщику не нужны.
